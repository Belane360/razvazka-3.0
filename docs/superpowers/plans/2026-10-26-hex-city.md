# Hex City Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans. Execute the user's four steps in order.

**Goal:** Offline two-level hex transport simulation with 2–6 hex ramps.
**Architecture:** Pure TypeScript graph and simulation; procedural Three scene; React HUD.
**Tech Stack:** TypeScript strict, React 19, Three.js, Vite, node:test.
**Spec:** ../specs/2026-10-26-hex-city-design.md, amended by the user's 2026-10-26 ramp specification (takes precedence).

## Global Constraints
- ground/elevated independent; rampSpan integer 2..6.
- No U-turns on elevated roads; fixed 60-degree exits.
- No external runtime resources, road Beziers, boolean triangulation or UI dependencies in core.

## Review Focus
- Invalid ramp placement must be atomic (task 2).
- Cross-level adjacency must not silently connect (task 2).
- Lane endpoints and tangents must match across hex boundaries (task 2).
- Traffic must brake for leaders beyond the current lane and red signals (task 3).
- Removal of a ramp must invalidate routes safely (tasks 2/3).

## Decisions / progress
- New empty repository: work in the user's supplied workspace; no existing implementation to isolate.
- Ramp span counts adjacent hex intervals, so a span N contains N+1 centerline coordinates, including both endpoints. UI states this explicitly.
- Ramps follow a straight hex axis, use a cubic smoothstep height profile (not a road Bezier), and reject occupied interior elevated slots. Elevated turns permit straight or +/-60 degrees; no 120-degree hairpins or U-turns.
- Latest request defines an architectural template; scene remains a playable procedural demonstrator with construction and HUD, not a complete balanced campaign.
